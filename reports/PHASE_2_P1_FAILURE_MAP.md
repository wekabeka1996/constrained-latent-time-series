# Phase 2 P1: Forensic Failure Map

This report details a forensic mapping of previous or current failure modes in the `constrained-latent-time-series` repository, classifying the risks associated with structural validity, layouts, data leakage, configurations, metrics, and training pipeline discipline.

---

## 1. Structural Validity Failure

### treat-numeric-as-valid Risk
In the legacy codebase, numeric output vectors from the VAE decoder (which uses a final `Tanh` layer mapping values to `[-1, 1]`) are treated as structurally valid models without any architectural validation or constraint enforcement. 
* **Decoder Output**: The VAE decoder output is simply a continuous vector of float values. There is no layer or mapping to guarantee:
  1. Autoregressive stability: roots of the characteristic polynomial $1 - \sum \phi_i z^i = 0$ lying strictly outside the unit circle.
  2. GARCH volatility stability: positive intercept ($\omega > 0$), non-negative coefficients ($\alpha_i \ge 0, \beta_j \ge 0$), and persistence covariance-stationarity ($\sum \alpha_i + \sum \beta_j < 1$).
* **Verification**: Stage 4 validation of the pre-trained weights (`vae_beta50.pth`) shows a **0.0%** reconstruction validity rate due to `LEGACY_LAYOUT_COLLISION`.

### Implicit Family Structure
There is no explicit representation of the model family in the network's structural slice. The family is determined solely by comparing continuous indicator variables against a threshold ($0.5 \pm 0.05$). The model doesn't enforce disjoint activation, so both ARMA and GARCH indicators can be active at the same time (which is the case for 100% of VAE reconstructions in the baseline).

## 2. Layout Collision Risk

### Overloaded Slots
The 40-dimensional parameter vector layout features severe slot overloading:
* **Index 10 (`v[10]`)**: Represents the first autoregressive coefficient ($\phi_1$) in ARMA models, but GARCH intercept ($\omega$) in GARCH models.
* **Overlapping Coefficients**:
  - In ARMA, parameters from index 10 onward are AR coefficients ($\phi_1, \phi_2, \dots$).
  - In GARCH, parameter 10 is $\omega$, and parameters from index 11 onward are ARCH ($\alpha$) and GARCH ($\beta$) coefficients.
* **Collision Consequences**: A single position (`v[10]`) carries completely different mathematical interpretations depending on which family indicator is active.
* **Undefined Hybrid Layout**: Because of this collision, a combined ARMA-GARCH model has **no defined layout representation** in the codebase. 

### Ambiguous Indices in Experimental Code
In the experimental data script [generate_enriched_training_data.py](file:///c:/Users/wekab/Music/constrained-latent-time-series-main/constrained-latent-time-series-main/src/generate_enriched_training_data.py), a non-canonical layout is written:
- `x[0] = 1` (AR indicator)
- `x[1] = 1` (MA indicator)
- `x[2] = 0` (GARCH indicator)
- `x[3] = p`, `x[4] = q` (writing raw integer orders instead of Continuous Logits)
- `x[10:10+p] = phi` (AR)
- `x[20:20+q] = theta` (MA)
This layout contradicts the canonical [vector_schema.py](file:///c:/Users/wekab/Music/constrained-latent-time-series-main/constrained-latent-time-series-main/src/vector_schema.py) which maps the structural slice to `v[0:10]` and expects continuous logits inside `[-1, 1]` for orders, causing severe scaling and layout collisions when fed into the VAE.

## 3. C Leakage Risk

### Zero-Shot Generalization Leakage
Phase 2 evaluates whether a VAE trained on disjoint model families (A = AR/ARMA, B = GARCH) can generalize to generate a third hybrid family (C = ARMA-GARCH).
* **Leakage via Data Generation**: If any training dataset contains hybrid models (such as the ARMA models generated by `generate_enriched_training_data.py`), it invalidates the "zero-shot" generalization claims of the model.
* **Default Mixes**: The default dataset generator `data_generator.py` generates pure AR and GARCH models disjointly. However, there is no split contract or validation check to verify that hybrid models are strictly excluded from the training split.

## 4. Hardcoded/Default Config Risk

### Argument and Dataclass Defaults
Numerous defaults are hardcoded in the codebase, creating a risk that missing config keys will silently fail over to hidden defaults rather than crashing the execution:
1. **Pydantic Schema Defaults** (`src/config.py`):
   - `project.mode = "demo"`
   - `model.checkpoint_role = "unspecified"`
   - `generation.seed = 42`
   - `generation.allow_supervised_arma_garch = False`
   - `generation.synthetic_training_data_is_methodology = False`
   - `paths.market_data_csv = None`
   - `integrity.allow_random_fallbacks = False`
   - `integrity.allow_fake_market_data = False`
   - `integrity.allow_cached_artifacts = True`
   - `integrity.require_artifact_provenance = True`
   - `integrity.fail_fast_on_missing_required_artifacts = True`
   - `geometry.max_geometry_points = 32`
   - `geometry.finite_difference_eps = 1e-4`
   - `geometry.metric_regularization_eps = 1e-8`
2. **VAE constructor defaults** (`src/vae.py`):
   - `d_input = 40`, `d_latent = 8`, `d_hidden1 = 64`, `d_hidden2 = 32`.
3. **Generator config defaults** (`src/data_generator.py`):
   - `n_arma = 100`, `n_garch = 100`, `seed = 42`, `max_lag_order = 5`.
4. **Validation defaults** (`src/validation.py`):
   - Threshold `0.5`, epsilon `0.05` for discrete structure decoding.
5. **Standalone training script defaults** (`src/train_vae_model.py`):
   - Default epochs = 100, seed = 42, beta = 1.0.

* **Risk**: Any missing field in the configuration YAML file is silently filled with these defaults, violating strict config discipline.

## 5. Metric Drift Risk

### Ad-hoc Metrics
Validation rules and decision boundaries are defined as function parameters with defaults in `src/validation.py` rather than being frozen in a centralized, read-only configuration contract. This makes it possible for different scripts or future extensions to import validation checks but override the thresholds (e.g. changing threshold from 0.5 to 0.1 to artificially inflate "validity" rates).

## 6. Reproducibility Failure

### Legacy Mathematical Bug (P0 Jacobian)
The legacy Fisher metric script `archive/invalidated_geometry/compute_fisher_metric.py` had a critical mathematical bug:
* **The Bug**: Instead of computing the full Jacobian matrix $J = \frac{\partial \theta}{\partial z}$ and forming the pullback metric $G = J^T J$, the code attempted to compute metric values using a 1D division, producing mathematically meaningless outputs.
* **Consequences**: All claims regarding 2D manifolds, geodesic shortening, and regularized Fisher metric distances in the legacy literature were completely invalidated.

### Hardcoded File Paths in Archive
Many archived scripts contain hardcoded local file paths and output paths, which prevent execution on different machines.

### Swapped Uniform Bounds Bug
The legacy generator Swapped Low/High Bounds in uniform distributions when GARCH persistence exceeded bounds, leading to negative betas and explosive persistence parameters. This is reproduced in `legacy_compatible` mode but represents a mathematical violation.

### Artifact Overwriting
