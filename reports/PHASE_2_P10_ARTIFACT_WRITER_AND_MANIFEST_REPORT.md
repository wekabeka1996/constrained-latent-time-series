## 8. Artifact Writer Design Implemented
The writer defines:
- `ArtifactWriteRequest`: Immutable container with no default values/factories for `dataset_result`, `output_dir`, file names, overwrite controls, option inclusion flags, and JSON styling parameters.
- `ArtifactWriteResult`: Immutable container describing the result directory, absolute file paths, SHA256 hashes, counts, and metadata.
- `validate_artifact_write_request(request)`: Validates request types/values and checks path safety (ensuring no directories are deleted/modified outside the target output path).
- `write_dataset_artifacts(request)`: Executes validation, creates the output directory if allowed, serializes samples into JSONL format, writes them to disk in binary mode, computes the SHA256 hash of the written bytes, constructs the manifest JSON, serializes the manifest, writes it to disk, hashes the manifest, and returns the write result.

## 9. JSONL Sample Schema
Each line represents a single `DatasetSample` encoded as a single-line compact JSON object:
- `sample_id`: `str`
- `protocol_name`: `str`
- `split_name`: `str` (from `SplitName` enum)
- `family_id`: `str` (from `FamilyId` enum)
- `sample_index`: `int`
- `generation_seed`: `int`
- `simulation_seed`: `int`
- `model_spec`: JSON object with:
  - `family_id`, `mean_family`, `volatility_family` (serialized as strings)
  - `p`, `q`, `r`, `s` (`int`)
  - `ar_params`, `ma_params`, `alpha_params`, `beta_params`, `constraint_flags` (JSON lists of floats)
  - `omega` (`float` or `null`)
  - `provenance` (JSON list of lists/tuples of strings)
- `provenance`: JSON list of lists of strings
- `values` (optional, list of floats)
- `innovations` (optional, list of floats)
- `variances` (optional, list of floats)

Even if `json_indent > 0` is set, samples are always written as a single compact line per sample to conform to JSONL specification.

## 11. SHA256 Behavior
To avoid platform-dependent newline transformations (which would alter file hashes), the files are serialized to UTF-8 encoded bytes in memory and written via `Path.write_bytes()`. The SHA256 hash is computed over the exact bytes written to disk. The helper `sha256_file(path)` reads the file in binary mode to calculate and return the lowercase hex digest.

## 12. Overwrite Behavior
If `overwrite_existing` is `False`, `write_dataset_artifacts` checks if either target file exists and raises a `FileExistsError` before writing. If `overwrite_existing` is `True`, it overwrites existing files. It never deletes the output directory or performs recursive removal.

## 13. Determinism Evidence
Tests 42 and 43 verify that the exact same dataset result written to two different directories generates identical samples SHA256 hashes and identical manifest content (and manifest SHA256 hashes). The manifest does not embed absolute paths (using relative `samples_filename` instead), preserving hash determinism across different execution hosts and target directories. Test 44 confirms that reordering dataset samples results in a different samples hash.
