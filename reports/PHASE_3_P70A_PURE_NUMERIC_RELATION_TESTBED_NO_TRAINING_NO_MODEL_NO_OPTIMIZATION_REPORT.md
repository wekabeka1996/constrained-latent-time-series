# PHASE 3 P70A Pure Numeric Relation Testbed Report

## 1. Problem Framing
P70A is the pure numeric relation testbed package following P69. It establishes a controlled vector coordinate world where exact vector transformations (relation types) are known and mapped across multiple base states. It provides a simple testbed to evaluate baselines vs. future relation models before moving to complex GARCH/temporal time-series.

## 2. Boundaries and Scope
We strictly respect the Phase 3 boundaries:
- No training loop is implemented.
- No model architecture or parameters are instantiated.
- No optimization step is performed.
- No PyTorch or NumPy is imported.
- No stochastic random functions are used.
- No Schrödinger Bridge or Geometric Schrödinger Bridge is built.
- No semantic geometry, meaning, or operator identity claims are made.
- Testbed records are static fixtures and are explicitly not training data.

## 3. Why Repeated Relation Instances are Mandatory
A relation/operator must generalize beyond a single start/end pair. Future relation modules `R(z_A, z_B)` must distinguish the reusable relation identity (e.g. translate_x) from the specific coordinate pair (A→B). By applying the same relation type to multiple distinct base states, we force the testbed to verify whether relation operators can be disentangled from base coordinates.

## 4. Relation Types
We implement five deterministic transformations over 3D states `[x, y, s]`:
1. **translate_x**: `[x + intensity, y, s]`. Changes index 0, invariants: 1, 2. Composition family: translation.
2. **translate_y**: `[x, y + intensity, s]`. Changes index 1, invariants: 0, 2. Composition family: translation.
3. **scale_s**: `[x, y, s * (1.0 + intensity)]`. Changes index 2, invariants: 0, 1. Composition family: scale.
4. **reflect_x**: `[-x, y, s]`. Changes index 0, invariants: 1, 2. Composition family: reflection. Self-inverse.
5. **nonlinear_x_from_y**: `[x + intensity * (y^2 + 1), y, s]`. Changes index 0, invariants: 1, 2. Composition family: nonlinear shear.

## 5. Splits and Evaluation Records
- **train_style_repeated_instances**: Repeated combinations of relation types and intensities on 4 train-style base states.
- **heldout_base_state**: Relations applied to 2 held-out base states.
- **heldout_magnitude**: Intensity-sensitive transformations using a held-out intensity magnitude `2.0` on train-style base states.
- **heldout_composition**: Sequence of transformations (e.g., `translate_x` then `translate_y` [commutative] vs. `reflect_x` then `translate_x` [order-sensitive]).
- **negative_control**: Includes label permutation and mismatched pairs where base state source identity conflicts.

## 6. Negative Controls
- **Label Permutation**: Actual transformations mapped to cycled incorrect relation types.
- **Mismatched Pairs**: Associating `z_a` and `z_b` from different base states to violate relation identity.

## 7. P69 Validation
P70A validates the P69 baseline contract before returning `P70A_READY_FOR_REVIEW`. This checks that all five mandatory baselines exist, no-torch/no-numpy rules are respected, and P68 contract validated successfully.
