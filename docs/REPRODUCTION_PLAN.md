# VAE Econometric Manifold Reproduction Plan

This document outlines the systematic, end-to-end plan to reproduce the experimental results after the completion of the configuration, geometry correctness, and fail-fast cleanup phases. 

To maintain strict research integrity, the reproduction run must never overwrite legacy results and must track all artifact relationships through a signed execution manifest.

---

## 1. Directory Structure

Every reproduction run is isolated into a timestamped directory inside `results/`. The structure is organized as follows:

```text
results/reproduction_<YYYYMMDD_HHMMSS>/
  config_snapshot.yaml      # Copy of configs/demo.yaml used in this run
  manifest.json             # Execution metadata, file hashes, and verdicts
  data/                     # Synthetic data files (training and labels)
  latent/                   # Extracted latent representations (Z_train, Z_generated)
  validation/               # Model validation results (orders, validation statistics)
  geometry/                 # Corrected pullback geometry metrics and geodesics
  empirical_stress_test/    # Results of the real-world out-of-domain historical stress test
  plots/                    # Regenerated visual plots
  reports/                  # Run execution logs and summaries
```

## 2. Artifact Classification Inventory

Before comparing outputs, every artifact in the repository is classified to define its provenance:

| Path / Pattern | Classification | Description |
| --- | --- | --- |
| `data/generated/Z_train.npy` | GENERATED_LEGACY_VALID | Training dataset generated by prior pipeline. |
| `data/generated/train_labels.npy` | GENERATED_LEGACY_VALID | Group labels for training datasets. |
| `data/generated/generated_valid_thetas.npy` | GENERATED_LEGACY_VALID | Valid parameters generated from VAE. |
| `models/*.pth` | MODEL_CHECKPOINT | Trained model weights (e.g., `vae_beta50.pth`). |
| `results/generation_1/fisher_metrics/*.npy` | GENERATED_LEGACY_INVALID | Invalid pullback metrics due to Jacobian bug. |
| `results/generation_1/regularized_fisher/*` | GENERATED_LEGACY_INVALID | Invalid regularized metrics due to Jacobian bug. |
| `results/generation_1/plots/*.png` | GENERATED_LEGACY_SUSPICIOUS | Suspect plots since they plot invalid geometry. |
| `results/generation_2/robustness/*` | GENERATED_LEGACY_VALID | Robustness backtest logs (factual negative result). |

> [!CAUTION]
> Old artifacts in generation 1 are invalid and MUST NOT be used as baselines. Never overwrite them or use them as expected values in tests.

## 3. Reproduction Stages

> [!WARNING]
> Do NOT run legacy commands (e.g. `python src/compute_fisher_metric.py`) directly. Always use the reproduction runner, as running scripts directly bypasses the config validation and fail-fast guarantees.

Reproduction executes in sequential stages. If a dependency stage fails or is marked missing, subsequent stages fail-fast.

### Stage 0: Environment & Config Validation
* **Task:** Load the reproduction config (`configs/demo.yaml`) and check that:
  * `integrity.allow_random_fallbacks` is `false`.
  * `integrity.allow_fake_market_data` is `false`.
  * `integrity.fail_fast_on_missing_required_artifacts` is `true`.
* **Output:** Stage validation record in `manifest.json`.

### Stage 1: Synthetic Methodology Dataset Generation
* **Task:** Run the data generator to reproduce the training data.
  * **Command:** `python src/data_generator.py`
  * **Rule:** Clearly identify generated arrays as methodology synthetic data, never empirical data.
* **Output:** `Z_train.npy` and `train_labels.npy` inside the reproduction directory.

### Stage 2: VAE Checkpoint Verification
* **Task:** Load the trained VAE checkpoint (`vae_model_weights.pth` or specified path in config).
  * **Task:** Run a verification forward pass using synthetic vectors and check sizes.
* **Output:** Verification logs.

### Stage 3: Latent Representation Extraction
* **Task:** Run latent vector extraction using the verified checkpoint and training data.
  * **Command:** `python -m src.reproduce --config configs/demo.yaml --stages 1,2,3`
  * **Rule:** No random fallback is allowed. If input datasets or model checkpoints are missing, fail fast.
* **Output:** `z_train.npy` (deterministic encoder mean), `z_train_ar.npy` (split by AR), `z_train_garch.npy` (split by GARCH), `mu_train.npy`, and `logvar_train.npy`.

### Stage 4: Structural Validity Assessment
* **Task:** Assess the discrete structural parameters and compute model type proportions.
  * **Command:** `python src/Симуляція_2.py`
* **Output:** `orders_generated.npy` and structural classification summaries.

### Stage 5: Corrected Geometry Pulldown
* **Task:** Compute the mathematical pullback Fisher information metric and geodesic lengths.
  * **Command:** Run `src/geometry.py` algorithms over the extracted trajectories.
  * **Rule:** Do NOT compare the new outputs to the legacy `results/generation_1/fisher_metrics` as expected targets, since the legacy metrics are invalid.
* **Output:** Pullback metrics and corrected path lengths.

### Stage 6: Empirical Stress Testing
* **Task:** Run the historical evaluation module against real-world assets.
  * **Command:** `python src/experiments/backtest_vae_models.py`
  * **Rule:** If real market data is missing, fail fast or write `NEEDS_REAL_DATA` to manifest. Never generate fake market data.
* **Output:** `vae_backtest_summary.csv`.

## 4. Artifact Comparison Rules

To verify that the reproduction run is mathematically consistent:

### `.npy` Files
* Compare shape: must be identical.
* Compare dtype: must be equivalent (e.g. `float32` vs `float32`).
* Metrics: Compute `max_abs_diff` and `mean_abs_diff`. Use `np.allclose(a, b, atol=1e-5)` for validation datasets where random seeds were controlled.

### `.csv` Files
* Assert column names match exactly.
* Assert row counts match exactly.
* Compare categorical values exactly, and numerical values using a defined relative tolerance.

### `.png` Files
* Do not use pixel-perfect image comparisons as the primary verification metric.
* Verify plot generation by checking output existence. Inspect underlying coordinates for correctness.

### Pullback Fisher Geometry
* Old artifacts are classified as `INVALID_DO_NOT_CLAIM`.
* Do NOT use legacy Fisher artifacts as golden expected values. 
* Compare new geometry outputs against the mathematical invariants of the corrected pullback geometry module in `src/geometry.py`.
