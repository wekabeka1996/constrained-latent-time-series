# Phase 2 Model Boundary Contract

This document specifies the strict inputs, forbidden inputs, outputs, validation gates, run metadata, fail-fast rules, and compatibility boundaries with P23 for any future neural model candidate.

## 1. Inputs

The future model candidate must draw input representations only from:
- **Artifact-Backed Dataset Samples**: Deterministic datasets extracted from approved P14/P16 artifacts.
- **ModelSpec-Derived Structured Fields**: Parameter coefficients, classifications, and orders defined by the `ModelSpec` schema.
- **Optional Deterministic Series Diagnostics**: Statistical characteristics computed directly from raw series (e.g. sample variance, ACF/PACF coefficients, and volatility statistics).
- *Strictly no hidden fallback data or un-audited external resources are permitted.*

---

## 2. Forbidden Inputs

To preserve experimental integrity and prevent data contamination, the following inputs are strictly forbidden during zero-shot training:
- **Family C (ARMA-GARCH)** samples in the zero-shot training split.
- Generated Family C labels inside training targets for zero-shot mode.
- Local files or directories located outside the explicit, configured `artifact_root`.
- Synthetic fallback samples not produced by the accepted Phase 2 sampler/simulator/artifact stack.
- Hand-crafted or cherry-picked samples designed to artificially bypass constraints.

---

## 3. Outputs

The model candidate must produce outputs structured as:
- **ModelSpec Candidates**: Reconstructed parameter sets conforming to the `ModelSpec` schema.
- **Candidate Metadata**: Accompanying generation tracking fields (e.g. `candidate_id`, `model_architecture_id`, `seed`).
- **Evidence-Compatible Summary**: High-level execution summaries.
- *Strictly no raw parameters (such as weight matrices, raw coefficient arrays, or parameter keys) may leak into final normalized evidence.*

---

## 4. Required Validation Gates

All candidate specifications generated by the model must pass the following validation gates before being summarized:
1. **Schema Validation**: Verified using `validate_model_spec`.
2. **Math Validity Validation**: Verified using `require_math_valid`.
3. **Family C Zero-Shot Leakage Check**: Enforces that no composite specs were used in training when running in zero-shot mode.
4. **Evidence Normalization Check**: Verified via the P23 normalized evidence bundle mapping.
5. **Raw Parameter Leakage Check**: Ensured via the P23 safety checks (`assert_no_raw_params`).
6. **Forbidden Claim Check**: Verified via P23 `assert_no_forbidden_claims`.

---

## 5. Future Model Run Metadata

Every model execution must record and output a metadata block containing:
- `model_architecture_id`: Set to `FC-VAE`.
- `model_code_git_commit`: Git commit hash of the training/inference code.
- `training_artifact_root`: Repo-relative path to training artifacts.
- `training_split_contract`: Identifier of the split preset used.
- `seed`: Integer randomization seed.
- `zero_shot_mode`: Boolean indicating zero-shot execution status.
- `C_train_count`: Count of Family C samples present in the training set (must be 0 in zero-shot mode).
- `config_hash`: SHA-256 hash of the execution configuration.
- `evidence_contract_version`: Expected `evidence_contract_version` (e.g. `"phase2_p23_evidence_contract_v1"`).

---

## 6. Fail-Fast Rules

The execution system must fail-fast and terminate immediately if any of the following conditions occur:
- **Zero-Shot Contamination**: `zero_shot_mode` is True but `C_train_count` != 0. (System must fail).
- **Missing Artifacts**: The configured `training_artifact_root` or sample files are missing or unreadable. (System must fail).
- **Missing Configuration**: The execution configuration is missing required parameter keys. (System must fail).
- **Malformed Specification**: Model output cannot be successfully converted into a valid `ModelSpec`. (System must fail).
- **Normalization Failure**: The generated summary fails to normalize using the evidence contract. (System must fail).
- **Raw Parameter Leakage**: Any forbidden raw parameter key or key-value format is found in the final normalized evidence. (System must fail).
- **Local Path Leakage**: Any absolute path containing forbidden prefixes (such as file scheme, C drive prefix, /home, or /Users) is detected in the output or logs. (System must fail).

---

## 7. Boundary with P23

- The P23 `EvidenceBundle` serves as the canonical, normalized comparison format for all baselines and future model candidates.
- The future model must implement a translator that maps its candidate summaries into a P23-compatible baseline/model record format.
- All baseline vs. model comparisons must be performed using the normalized evidence structure only. No free-text claims or custom evaluation structures are permitted outside the P23 contract.
